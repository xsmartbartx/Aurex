# Validation

Every boundary validates what it receives (zero trust) and fails fast with one error structure.

| Boundary | Mechanism |
|---|---|
| API requests | Pydantic models with `extra="forbid"`; query bounds; UUID path parameters |
| Provider responses | Connector schemas (`Lenient` models) and canonical `Batch` objects (`Strict`); any violation fails the run |
| Uploaded CSV | `modules.validation.parse_csv`: size, UTF-8, required and unexpected columns, ragged rows, formula cells |
| Uploaded documents | `.txt`/`.md` only, size limit, UTF-8, no NUL bytes; passages screened |
| Model output | JSON schema enforced by the API (structured output), then parsed and every statement verified |
| Module calls | Services re-check entitlements, roles, limits and ownership instead of trusting the caller |

## Error structure

```json
{"error": {"code": "validation_failed", "message": "Invalid request",
           "details": {"issues": [{"field": "name", "problem": "Field required"}]}, "request_id": "…"}}
```

Codes: `validation_failed`, `unauthenticated`, `forbidden`, `csrf_check_failed`, `entitlement_denied`,
`license_denied`, `not_found`, `conflict`, `rate_limited`, `quota_exceeded`, `provider_*`, `internal_error`.
Input values are never echoed in error details.

## Quality status of values

`validated` (passed all rules), `suspect` (failed a rule: jump, non-positive price, inconsistent OHLC),
`estimated`, `demonstration` (generated by AUREX). The status travels with each point and is summarized
on charts.
